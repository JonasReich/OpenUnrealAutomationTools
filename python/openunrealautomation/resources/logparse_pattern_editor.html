What is this?  Read me — plain-English guide to the pieces

This file tells the build-log analyzer which lines in a build log are interesting, and how to label them. You mostly care about Rule groups and the rules inside them. The structural pieces (Templates, Targets, Scopes, Links) are shown read-only so you can see the layout without accidentally breaking it.

Rule group
A named bucket of one or more match rules that all share a severity and category (e.g. "Material Errors").
Rule (Include / Exclude)
Include = a line matching this is captured. Exclude = a line matching this is thrown out even if an Include matched. The first Include that matches a line wins.
Match style
Plain text (Literal): the line just has to contain this text (case-insensitive). Regex: a regular-expression pattern for advanced matching.
Severity
How the match is reported: Message · Warning · Severe Warning · Error · Fatal.
Tags
Categories like Code / Content / Art, used to filter the report.
Hidden
The group still matches lines but they are not shown in the report (used for background bookkeeping).
Variables
For Regex rules only: named pieces you capture out of the line (e.g. a file name or a number). The tool detects them for you.
Success / Failure flags
Marks a build step as passed/failed when the line matches. The common value is auto.
Scope
A region of the log between a Start line and an End line. Rules inside a scope only apply within that region. (Read-only here.)
Link
Reuses all the rules from another Template/Target by name, to avoid duplication. (Read-only here.)
